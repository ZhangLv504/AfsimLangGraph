# 阶段 5：验收补强

## 目标

- 补上阶段 2 遗留的 `domain` 与装备确定性检查。
- 过滤验收模型虚构的缺失项，避免“需求没写却判缺失”。

## 改动

### 平台域

[afsim_lg/graph/checks.py](../afsim_lg/graph/checks.py) 新增 `DOMAIN_HINTS`：

- 检查 `air` / `surface` / `subsurface` / `space` 四类非默认域。
- 通过 `spatial_domain <domain>` 或对应 mover（`WSF_AIR_MOVER`、`WSF_P6DOF_MOVER`、`WSF_SURFACE_MOVER` 等）判定。
- `land` 是 AFSIM 默认域（文档：`spatial_domain` 缺省 `land`），因此 `ground` 不检查，避免没写 `spatial_domain` 的地面雷达被误判。
- 关键字用标识符边界匹配，`RED_RADAR` 里的 `radar` 不会冒充雷达传感器。

### 装备

- 只解析 `sensor/weapon [add|edit] <名称> <类型>` 定义行的类型 token，不扫全文。
- 中文描述词表：传感器为雷达/红外/光学/声学/传感器；武器为导弹/火炮/炸弹/鱼雷/武器。
- 词表外的描述跳过；“传感器/武器”这类泛化描述只要有同类定义即通过。
- 例：需求写“雷达”，工程里只有 `WSF_GEOMETRIC_SENSOR` 会判失败；`WSF_RADAR_SENSOR` 通过。

### 验收缺失项过滤

新增 `filter_judge_missing(missing, requirement, contract)`：

- 契约没有该事件、需求原文也没有对应词（探测/发现/跟踪、发射/开火、命中/击中、摧毁/击毁/击杀）时丢弃。
- 契约 `expectations` 为空且需求没写“交战”时，丢弃泛化的“缺少交战”。
- 缺失项提到词表内的平台/装备（航母、战斗机、雷达、导弹等），但需求与契约都没出现时丢弃。
- 词表外的缺失项保留。

`assess` 集成：

- 过滤后若模型判失败的理由全部被丢弃、且没有其他缺失，改判通过。
- `assessment.json` 增加 `judge_filtered`，记录被丢弃的虚构项。
- `JUDGE_SYSTEM` 增加“missing 必须是需求原文出现过的名称；需求只写‘飞机’时，不要要求具体机型”。

### 报错规则

- 报错关键词新增 `Bad value for: X`，修复轮可检索到对应的模板/参考。
- 修复反馈提示“检查该命令的每一处引用是否都有同名定义块”，`REPAIR_SYSTEM` 同步明确。

## 验证

- 单元测试：42 passed（新增平台域、装备、验收过滤、assess 改判集成测试）。
- 手工雷达探针 `workspace/stage5-accept-probe`：`mission.exe` 退出码 0，evt 产生 1 条 `SENSOR_TRACK_INITIATED`；6 项检查全部 PASS（仿真时长、阵营覆盖、平台数量、平台域、装备:传感器、事件:detect）。
- 真实生成文件复评（`stage4-checks-e2e2` 的 attempt 文件）：平台域与装备:传感器 PASS；事件检查因 mission 失败、没有 evt 而 FAIL，符合预期。
- 真实生成 `stage4-checks-e2e` / `e2e2` / `e2e3` 均卡在 mission 阶段：先是 `Bad value for: antenna_pattern`，补提示后变成 `Unknown command: red_radar_sensor`，修复轮仍未消除。7B 生成质量仍是主要瓶颈；验收过滤的改判路径由单测与 assess 集成测试覆盖。

## 已知边界

- 词表有限，未识别的装备/平台跳过而不判失败。
- 中文按字面判断，否定句（“不需要探测”）可能让过滤失效。
- 只有在“所有缺失项都被过滤且无其他缺失”时才改判通过。
- `ground` 不检查域；`air/surface/subsurface/space` 依赖 `spatial_domain` 或 mover。
- `WSF_P6DOF_MOVER` 一律视为 air，可能误判，词表可扩展。
- 过滤只影响验收结论与反馈，不改模型原始 verdict；丢弃项保留在 `judge_filtered` 中。
- `架构.md` 由用户维护，本阶段未改。
