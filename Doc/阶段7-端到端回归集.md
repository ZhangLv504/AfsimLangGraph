# 阶段 7：端到端回归集

## 目标

- 把“简单飞行 / 雷达探测 / 发射”三类需求固化为可重复运行的回归集。
- 记录通过率、生成轮数与耗时，防止后续提示词改动造成回退。
- 单个用例失败或异常不中断整个回归集。

## 改动

新增 [afsim_lg/regression.py](../afsim_lg/regression.py)：

- `CASES`：`simple-flight`、`radar-detect`、`engagement-fire` 三类需求。
- `run_case`：执行完整图流程，记录状态、生成轮数、耗时、确定性检查、失败项，并从 `manifest.json` 提取每轮模式与结果。
- `run_all`：汇总 `total/passed/failed/pass_rate/generations/avg_generations/elapsed_sec`，写出 `report.json` 与 `report.md`。
- 默认报告目录：`workspace/regressions/<时间>/`。
- 单例抛异常时记录错误并继续，不中断回归集。

CLI 新增 `regress`：

```bash
.venv/Scripts/python.exe -m afsim_lg.cli regress --attempts 3
.venv/Scripts/python.exe -m afsim_lg.cli regress --case radar-detect
```

- `--attempts` 默认 3，`--case` 可重复，`--report-dir` 可指定输出目录。
- 全部通过返回 0，有失败返回 1，未知用例返回 2。

修复提示补充：

- `speed/altitude` 误写进 mover 时，提示放回 `route ... end_route`。
- 脚本编译失败时，提示 `script_variables` 数字不能带单位、语句要分号，修不好就删除脚本块。

- 回归耗时：约 80 秒/3 例（本机 7B）。

## 现有基线

- `radar-detect` 稳定通过（1-2 轮，6 项检查全 PASS）。
- `simple-flight` 的失败点可定位：模型把 `speed/altitude` 写进 mover；修复提示已包含正确做法，但 7B 未执行。
- `engagement-fire` 已能编译运行，但导弹未发射；需要进一步检查 weapon 挂载、launch computer、目标跟踪与发射条件。

## 已知边界

- 回归依赖真实 LLM 与 `mission.exe`，有随机性；通过率是抽样结果。
- `engagement-fire` 只要求发射，不要求命中。
- 报告与运行产物在 `workspace/` 下，不入库；文档只记录基线数字。
- 回归命令默认 3 轮，单次 `run` 命令默认仍是 2 轮。
- `架构.md` 由用户维护，本阶段未改。
