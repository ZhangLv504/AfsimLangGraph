# 阶段 6：修复鲁棒性

## 目标

- 针对 mission 反复出现的语法/结构错误，给修复轮确定性、可执行的指令。
- 生成规则补齐 `antenna_pattern`、`constant` 单位、`sensor` 归属。
- 用“红方地面雷达探测蓝方飞机”需求跑通一次端到端作为验收标准。

## 改动

[nodes.py](../afsim_lg/graph/nodes.py) 新增四类修复提示：

- `_unknown_command_hint`：
  - 普通未知命令：检查以它开头的整块，拼写错误改正，否则整块删除。
  - `Unknown command: end_X`：说明前面有块未闭合，补缺失的 `end_`。
  - `WSF_ANTENNA_PATTERN`：它不是 `antenna_pattern` 的基类型，删除后按 `antenna_pattern <名字>` + `constant/circular_pattern/rectangular_pattern` 子块重写。
- `_constant_hint`：`constant` 单位错误时明确区分——`antenna_pattern` 用 `db/absolute`，`radar_signature` 用 `m^2`。
- `_signature_hint`：静态定位“被引用但没有定义”的 `radar_signature`，直接点名要补的名字。AFSIM 只报 `Undefined radar_signature`，不报具体名字。
- `_detect_hint`：detect 事件未发生时，提示检查 sensor 是否在平台 `platform_type` 内、是否 `on`、距离是否覆盖、位置是否在范围内，并明确“不要删除已有平台”。

生成/修复提示词：

- 生成规则 11-14：`antenna_pattern` 引用必须有同名定义块、定义不带基类型、`constant` 单位按对象区分、`sensor` 必须放进 `platform_type`。
- 生成提示词附一个已验证的最小雷达骨架（天线方向图、签名、雷达 sensor、双方平台、位置）。
- 修复规则 8-12：覆盖上述错误与 `sensor` 归属，避免修复时删除平台。

## 已知边界

- 提示是启发式，7B 仍可能忽略；本次修复需要 2 轮，`max-attempts` 默认仍是 2（本次验收显式用 4）。
- `antenna_pattern` 未做静态硬检查：demos 里同名定义常在被 include 的其他文件，按文件集扫描会误报，故依赖提示 + mission 兜底。
- 没有验证 sensor 是否真的挂在平台上；“装备:传感器”只检查类型存在，detect 事件检查负责兜底。
- 生成有随机性，通过率尚未统计。
- 最小雷达骨架增加了提示词长度，长工程时上下文余量更薄。
- `架构.md` 由用户维护，本阶段未改。
